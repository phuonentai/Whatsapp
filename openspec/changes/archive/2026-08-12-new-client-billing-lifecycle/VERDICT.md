## Scope of this review

This review covers the post-revision-2 proposal/design/specs/tasks after the prior re-review verdict. All six previously-required changes were re-verified against the codebase and are correctly folded in:

1. **Error-classification contract (D1)** — Implemented and correct: `GetBillingStatus`/`RefreshSubscriptionStatus` return `domain.ErrSubscriptionNotFound` unwrapped (`get_billing_status_service.go`, `refresh_subscription_status_service.go`); the adapter translates it to `paywall.ErrNoSubscription` (`status_provider.go`); the middleware classifies sentinel → 402 `subscription_required` (status `none`), other error → 500 (`middleware.go`). `TestGetBillingStatus_ErrSubscriptionNotFoundPropagatesUnwrapped` pins the direct-equality requirement.
2. **Idempotent trial seeding (D2)** — Correct: `TrialSeeder` is a narrow organizations-domain interface implemented by billing infra (`infra/trial/seeder.go`), injected via dig (`billing/cmd/provider.go`); `member_service_impl.go` reads `TRIAL_ENABLED`/`TRIAL_DAYS`. `InsertLocalTrial`/`InsertLocalTrialQuota` use `ON CONFLICT (organization_id) DO NOTHING` and **real columns** — the phantom `invoice_count_max` was dropped by migration 000005 (renamed `invoice_count_current`→`invoice_count`, removed `invoice_count_max`); generated SQLC matches.
3. **Payment-method-update branching (D4)** — Correct, `billing-provider-ux` delta spec now exists (prior MED-1 resolved); Polar portal CTA with plans-modal fallback; MP honest copy, in-app PM update explicitly out of scope. `customerPortalUrl` confirmed absent from the FE snapshot — the open question stands, honestly flagged.
4. **UpgradeURL (D3)** — `DefaultMiddlewareConfig.UpgradeURL` is now `/dashboard/settings?view=subscription` (verified in `middleware.go`).
5. **Trial-expiry boundary (D6)** — The HIGH entitlement defect is fixed in code: `GetBillingStatus` classifies `trialing && now > current_period_end` as inactive (`Reason: "trial expired"`); the adapter maps it to `paywall.StatusUnknown` (≠ `StatusNone`), so the lazy guard fires; the refresh path refuses synthetic `local-trial-*` rows before any provider call. No indefinite invisible access.
6. **Observability (D7)** — `ListExpiredTrials` (`:many`, global) and `ListExpiredTrialByOrg` (`:one`, org-scoped, tenant-safe) both present in `subscription_billing.sql`.

## Per-persona findings

### 1. Staff Security Engineer

- **[MED-1] The flagship "Local-only trial expires" scenario documents a response the shipped mechanism cannot produce: `subscription_required` vs. actual `subscription_inactive`.**
  Traced end-to-end: an expired local-only trial makes the **fast path** `GetSubscriptionStatus` succeed — `GetBillingStatus` returns a status (not an error) with `HasActiveSubscription=false, Reason="trial expired"`. The middleware's `ErrNoSubscription → subscription_required` classification branch is therefore **never reached** (it fires only when the fast-path read itself errors — no row / DB failure). The lazy guard fires (`StatusUnknown ≠ StatusNone`), `RefreshSubscriptionStatus` fails closed with `ErrNoSubscription`, the original expired status is retained, and `buildErrorResponse` hits the default branch → **402 `subscription_inactive`, status `unknown`, message "trial expired"**. The design D6 claim ("fail closed → 402 `subscription_required` via the `ErrSubscriptionNotFound`/`paywall.ErrNoSubscription` classification") and the delta-spec scenario ("the response SHALL be HTTP 402 (`subscription_required` after classification)") both describe a mechanism that does not exist — the same class of spec-code contract error the council previously rejected on. Security outcome is correct (denied, fail-closed, no indefinite access), but the OpenSpec contract is authoritative, and a test asserting the scenario's own THEN clause would fail against the shipped code. Required change: correct D6 and the delta scenario to pin 402 `subscription_inactive` (status `unknown`, message "trial expired") and describe the real mechanism; optionally assert it in the E2E step.
- **[LOW] Synthetic-customer guard is implemented but not pinned by a test.** Verdict #2's required-change item 1 demanded "unit test asserts no provider call is made for synthetic rows" (tasks.md 3.2/3.3(c)). No test in the tree exercises `RefreshSubscriptionStatus` with a `local-trial-*` row (grep for `local-trial`/`synthetic` in `*_test.go` is empty). The guard exists in code; the exact defect class it prevents is the one thing untested.
- **[OK]** No credential storage; no Stytch contract changes; RBAC gates untouched; middleware error branch cannot emit a misleading 402 for DB failures once the 1.4 tests land; grace entitlement read-only posture unchanged.

### 2. Staff DBA

- **[OK]** No migrations; both trial inserts idempotent and safe under bootstrap retry; provider rows authoritative (`DO NOTHING` never overwrites); LEFT JOIN zeroed-quota default keeps trial rows visible with real status; `GetQuotaStatus`/`ListExpiredTrials`/`ListExpiredTrialByOrg` SQL verified against the post-000005 schema (real columns only).
- **[LOW] Deferred dunning scanner data-source gap (design D8):** the follow-up scanner is described as reading `ListActiveSubscriptions`, but that query filters `subscription_status = 'active'` only — it cannot enumerate `past_due` orgs for dunning. Note a `past_due`-scoped variant will be needed in the follow-up change; record it in the deferred scope so it is not assumed to exist.

### 3. Staff SRE

The boundary service test (`TestGetBillingStatus_TrialExpiredReportsInactive`) and the paywall unknown-status tests cover halves of the path, not the whole.

Polar portal availability and provider-trial-expiry semantics remain honestly flagged open questions with defined fallbacks. Rollback is clean (revert + unset `TRIAL_ENABLED`; no migration; no Stytch/provider impact).

## Required design changes (numbered)

1. **[MED] Correct the expired-local-only-trial contract in D6 and the `new-client-billing` delta spec ("Local-only trial expires" scenario).** Pin the actual shipped response: HTTP 402, error `subscription_inactive`, status `unknown`, message "trial expired", `upgrade_url` present. State explicitly that the `ErrSubscriptionNotFound`/`paywall.ErrNoSubscription` → `subscription_required` classification applies only when the fast-path read errors (no subscription row or DB failure) and therefore never fires for an existing expired trial row; the fail-closed 402 comes from the retained expired status through `buildErrorResponse`'s default branch after the lazy-guard refresh fails closed. Update the E2E/testing pin accordingly.
2. **[MED] Add the missing verification tests before the gate (tasks 1.4, 3.2, 3.3(c)):** (a) middleware: `ErrNoSubscription` → 402 `subscription_required` + status `none`; generic provider error → 500, never 402; (b) `RefreshSubscriptionStatus` on a synthetic `local-trial-*` row asserts the provider is NOT called and the outcome fails closed; (c) expired local-only trial full-stack deny test asserting the corrected error code from item 1.
3. **[LOW] Record in the D8 follow-up scope that the dunning scanner needs a `past_due`-scoped query** — `ListActiveSubscriptions` (status `active` only) cannot enumerate dunning candidates; do not assume it exists in the deferred design.

## Summary

The revision genuinely fixes the HIGH entitlement defect and folds in every prior required change; the design is sound, well-verified, and the security outcome (fail-closed, no indefinite access) is achieved in code. However, the flagship trial-expiry scenario's documented response contract is factually wrong (`subscription_required` cannot be produced by the described mechanism — the code returns `subscription_inactive` with reason "trial expired"), and the council-required tests for the synthetic-customer guard and middleware classification are still absent. Both fixes are small, surgical, and testable. Rejected until item 1 (contract correction) and item 2 (tests) land.
