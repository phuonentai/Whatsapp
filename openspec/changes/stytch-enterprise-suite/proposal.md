# Stytch Enterprise Suite

## Why

The product consumes only a fraction of the Stytch B2B free tier (magic links, sessions, RBAC, org/member management, in-flight TOTP MFA + passkeys). The free tier includes the full auth suite with **no feature gating** — SSO (SAML/OIDC, 5 connections), SCIM provisioning (5 connections), OAuth social login, email OTP, JIT provisioning, and the org discovery flow — plus pre-built UI (login + Admin Portal) that eliminates building these surfaces by hand. For a B2B WhatsApp CRM targeting companies, SSO is the classic enterprise procurement gate ("do you support SSO?"), SCIM is the follow-on lifecycle ask, and OAuth + email OTP reduce sign-in friction. All of it is $0 within the free tier (10K MAU, 5 SSO/SCIM connections, 1K M2M tokens, unlimited orgs — figures per stytch.com/pricing 2025, see design `## Assumptions` for the dated re-verification task); the only *paid* auth capabilities (Audit Logs at $799/mo, bot detection, intelligent rate limiting, branding at $99/mo) are consciously out of scope. Two living specs currently contradict each other on exactly this question (`crm-frontend` mandates pre-built Stytch components; `stytch-nextjs-components` removed those mandates in favor of a custom flow) — this change resolves that contradiction in the "adopt the Stytch surface" direction.

## What Changes

- **Login surface** (`/auth`): replace the custom email-only form with the pre-built `@stytch/nextjs/b2b` `<StytchB2B>` component in Discovery mode (Spanish locale per D8) — email magic links, OAuth social (Google/Microsoft, dashboard-configured), email OTP, and passkey sign-in rendered by the Stytch UI. Stytch's *org creation* via discovery stays DISABLED; the platform's governed `POST /auth/signup` (trial seeding, slug conflict handling, rollback, structured errors per `signup-stytch-compliance`) remains the only org-creation path. `/authenticate` (token consumption + MFA/passkey continuation) is unchanged. Unknown-address discovery sends are no longer suppressible in-process (the pre-built UI always sends); the spam/abuse posture is documented in `STYTCH_CONFIGURATION.md` (see Risks in design).
- **JIT provisioning (join, not create)**: per-org opt-in domain-restricted join — org admins may enable `email_jit_provisioning: RESTRICTED` + `email_allowed_domains` so teammates with a company domain join automatically (this also enables OAuth JIT for verified provider emails on those domains — stated in the UI/docs). Default remains `NOT_ALLOWED`; org creation via JIT is never enabled. JIT-joined members get the default `stytch_member` role.
- **SSO (SAML + OIDC)**: per-org connections managed through the free **Admin Portal** (`AdminPortalSSO`) mounted in settings (pending the task-3.2 availability gate; documented Go-backed fallback if the pinned SDKs lack the exports); per-org SSO JIT enabled by the admin through the auth-policy surface (`sso_jit_provisioning: RESTRICTED` scoped to the org's connections — least privilege; JIT-provisioned members get Stytch's default `stytch_member` role); SSO-capable orgs can set SSO as primary auth via `sso_default_connection_id`.
- **SCIM provisioning**: per-org SCIM connections through the free **Admin Portal** (`AdminPortalSCIM`, same availability gate) — base URL, bearer token, and group→role mapping are managed entirely in Stytch; nothing is stored locally.
- **Backend surface**: one new governed seam mirroring the `MfaPolicyUpdater` pattern — `OrgAuthPolicyUpdater` reading/writing org auth policy (`email_jit_provisioning`, `email_allowed_domains`, `auth_methods: RESTRICTED` + `allowed_auth_methods` [SDK values: `magic_link`, `email_otp`, `sso`, `google_oauth`, `microsoft_oauth`], `sso_jit_provisioning` + `sso_jit_provisioning_allowed_connections`, `sso_default_connection_id`) via `PUT /v1/b2b/organizations/{organization_id}`, breaker-guarded, `org:manage`, display-only mirror (never consulted for authorization). First write preserves existing orgs' current method set.
- **Spec reconciliation**: `stytch-nextjs-components` (login custom form → pre-built StytchB2B; settings scoped: members stay custom, SSO/SCIM via Admin Portal) and `crm-frontend` ("Auth pages use pre-built Stytch components" → login = StytchB2B discovery, settings = AdminPortalSSO + AdminPortalSCIM, member management stays custom) are brought into agreement; `auth-email-check` is re-scoped to remaining callers (the login form no longer performs the check).
- **Docs**: `STYTCH_CONFIGURATION.md` updated with the new dashboard config (products enabled, OAuth providers, billing verification prerequisite, SSO/SCIM connection budget, email-spam/abuse posture, branding note).

## Capabilities

### New Capabilities
- `stytch-login-surface`: pre-built Stytch B2B login (discovery mode, org creation hidden, Spanish locale), OAuth social login, email OTP as an additional primary method, per-org JIT domain join, `/authenticate` continuation unchanged.
- `enterprise-sso`: SAML/OIDC connections via Admin Portal, per-org SSO JIT (admin-enabled, `RESTRICTED` + allowed connections, default member role), SSO-as-primary org policy, org `org:manage` gating.
- `scim-provisioning`: SCIM connections via Admin Portal, group→role mapping, secrets never stored locally.

### Modified Capabilities
- `stytch-nextjs-components`: login page requirement reversed from custom email form to pre-built `<StytchB2B>`; settings requirement scoped so SSO/SCIM views use Admin Portal components while member management stays custom.
- `crm-frontend`: "Auth pages use pre-built Stytch components" requirement reconciled — `/login` renders `<StytchB2B>` with Discovery; `/settings` renders `<AdminPortalSSO />` and `<AdminPortalSCIM />`; member management remains the shipped custom UI.
- `auth-email-check`: the auth page no longer performs the email existence check; the shared-client-config resolution rule is re-scoped to the endpoint's remaining callers.

## Impact

- **Frontend**: `app/auth/page.tsx` → pre-built `<StytchB2B>` (Discovery, org-creation hidden, Spanish locale); settings gains `?view=sso` and `?view=scim` Admin Portal mounts (`AdminPortalSSOMountOptions`, `AdminPortalSCIMMountOptions`) gated by `org:manage` (subject to the task-3.2 availability gate — version bump or Go-backed fallback); settings `?view=access` gains a JIT policy toggle (domain join + SSO-JIT) posting to the new backend endpoint; custom login form + its `check-email` usage and `sendMagicLink` action are retired (kept only if other callers remain); `/authenticate`, MFA, and passkey flows untouched.
- **Backend**: `internal/modules/organizations` gains `OrgAuthPolicyUpdater` domain interface + Stytch adapter implementation (`PUT /v1/b2b/organizations` through the existing two-tier circuit breaker, 503 on breaker-open for read and write) + `GET/PUT /api/organizations/auth-policy` handlers gated `org:manage` — mirroring the shipped `MfaPolicyUpdater` pattern. No new tables, no DB migration.
- **Dependencies**: none new in Go; frontend already depends on `@stytch/nextjs/b2b` / `@stytch/vanilla-js` — the earlier claim that the Admin Portal exports "already ship in the pinned versions" is NOT verified (`@stytch/vanilla-js@5.41.0` / `@stytch/nextjs@21.15.1` expose no `AdminPortalSSOMountOptions`/`AdminPortalSCIMMountOptions`/`client.portal` in their type surface); task 3.2 decides between a reviewed version bump (which updates this claim) and the documented Go-backed fallback.
- **Stytch tenant policy state**: products enabled per project (test + prod), OAuth providers registered, per-org SSO/SCIM connections and JIT settings become managed tenant state. Billing verification on the Stytch project is a go-live prerequisite for sending magic links to arbitrary customer emails.
- **Pricing posture**: free within 10K MAU / 5 SSO+SCIM connections / 1K M2M; the 6th SSO or SCIM connection costs $125/connection/mo (documented budget, pass-through to the Enterprise tier — see design `## Market & Unit Economics`); OAuth social is not connection-billed; Stytch-branded emails are accepted (custom branding is $99/mo — skipped).

## Rollback

- **Git**: revert the change — frontend (auth page, settings views, retired actions), backend (auth-policy endpoint + adapter), docs. No migration exists, so no DB rollback is required.
- **Stytch tenant policy state**: per-org reversible — SSO/SCIM connections deleted via the Admin Portal (or fallback CRUD) / `DELETE /v1/b2b/sso/{connection_id}`; org auth settings restored via `PUT /v1/b2b/organizations/{organization_id}` (JIT back to `NOT_ALLOWED`, `auth_methods` back to `ALL_ALLOWED`/prior set, `sso_jit_provisioning` back to `NOT_ALLOWED`); products can be disabled per project. OAuth/OTP enablement is project-level and reversible in the dashboard.

## Non-Goals

- **NO local credential storage**: SSO certificates/client secrets, SCIM bearer tokens, OTP codes, and JIT secrets live exclusively in Stytch; the local DB stores only the org's displayed auth-policy mirror (read from Stytch on fetch, never consulted for authorization).
- NOT enabling Stytch discovery *org creation* or JIT org creation — the platform `POST /auth/signup` remains the sole creation path (trial seeding + slug governance preserved); `email_jit_provisioning` is only ever `RESTRICTED` or `NOT_ALLOWED`.
- NOT SMS OTP (per-message cost, Colombia country allowlist complexity — see `mfa-totp-enrollment` Non-Goals).
- NOT paid Stytch add-ons: Audit Logs ($799/mo — the project's own audit log remains), bot detection, CAPTCHA, intelligent rate limiting, custom authorization verdicts (custom in-process limiters remain), branding ($99/mo — Stytch-branded emails accepted).
- NOT M2M tokens, user impersonation, device fingerprinting, Stytch webhooks, or event-log streaming — tracked as follow-up changes (waves 2/3 of the free-tier gap analysis).
- NOT adopting `AdminPortalMemberManagement`/roles editing — the shipped `equipo-permisos` member UI and the in-flight `custom-roles-editor` change remain the member/role surfaces; only SSO and SCIM management move to the Admin Portal.
